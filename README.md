# qyekq

企业微信上下班提醒。到点给启用的人发应用消息。已经打卡或当天请假的人跳过。

## 环境

- Python 3.12
- 可选：Redis。连不上时令牌和调度锁记在当前进程里，重启后重新取

## 配置

在项目根目录放 `.env`。这个文件不会提交。

```text
QYEBOT_REDIS_URL=redis://127.0.0.1:6379/0
QYEBOT_DB_PATH=data/qyebot.sqlite
QYEKQ_USER=qyekq
QYEKQ_PASSWORD=qyekq
```

Redis 有密码时写成 `redis://:密码@主机:6379/0`。

`QYEKQ_USER` 和 `QYEKQ_PASSWORD` 只在这台机器第一次建立登录账号时生效。库里已经有账号之后，再改这两项不会替换旧密码。

相对路径的数据库文件按项目根目录解析。

## 安装和启动

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.venv\Scripts\python.exe run.py
```

Linux 上把 `.venv\Scripts\python.exe` 换成 `.venv/bin/python`。

浏览器打开 http://127.0.0.1:8787

`run.py` 只监听 `127.0.0.1:8787`。要用别的机器访问，把其中的 host 改成 `0.0.0.0`。

## 登录

第一次启动后的默认账号和密码都是 `qyekq`，以 `.env` 里第一次写入数据库的值为准。

未登录时，提醒、人员、班次、记录、连接都会停在登录页。

## 企业微信

在「连接」页填写企业 ID、AgentId、Secret，然后点测试连接。Secret 只存在本机 SQLite，接口只返回末四位。

自建应用需要：

- 发送应用消息
- 打卡：配置到「打卡 - 可调用接口的应用」。用来跳过已经打卡的人
- 审批：配置到「审批 - 可调用接口的应用」。用来读取请假审批单
- 通讯录读取：只在需要从企业微信同步人员时使用
- 服务器出口 IP 加入企业微信可信 IP

不拷数据库就在新机器的连接页重新填写。拷贝 `data/qyebot.sqlite` 时，连接信息和登录账号会一起过去。

## 页面

- 提醒：规则列表。每条规则有上班或下班、提前或延后的分钟数、接收人。右上角新增提醒
- 人员：手工添加，或从企业微信同步。可单独停用
- 班次：上下班时间和星期。放假、补班按日期手工添加。标成放假的日期不发；标成补班的日期照常发。系统不会自动拉取法定节假日
- 记录：已发送、已跳过、失败
- 连接：企业微信凭证和测试消息

同一人、同一规则、同一时点只发一次。

## 请假

每天 6:30（上海时间）增量拉取请假审批单。第一次会补近 28 天，之后只拉上次成功时间之后的新单，并重叠 2 分钟。本地只保留近 28 天。

用的接口：

- `POST /cgi-bin/oa/getapprovalinfo`
- `POST /cgi-bin/oa/getapprovaldetail`

只认标准请假控件（`Vacation`，类型为请假）且状态为已通过的单。驳回、撤销、通过后撤销会从本地去掉。

到点时用请假的起止时间对照上下班时刻。落在区间内就跳过，记录写「当天请假」。6:30 之后才审批通过的假，要到下一次 6:30 才进本地。审批接口失败时停 30 分钟再试，不打断发提醒。

## 令牌

企业微信 `access_token` 缓存在 Redis 键 `qyebot:token:{企业ID}`。有效期使用接口返回的 `expires_in` 再提前 200 秒。缓存没有或令牌失效时才重新拉取。Redis 不可用时，同一套有效期记在当前进程内存里。
